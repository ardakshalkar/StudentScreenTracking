A teacher website.
A student extension.

Your teacher or school must first run the Classroom Screen Sharing backend and dashboard. Installing the extension alone does not create a server. Ask your teacher for the HTTPS server address and an active classroom code.

Students: join and share

  1. Install Classroom Screen Sharing from its official Chrome Web Store listing once published, and pin it. Before publication, your administrator can build it and use Chrome's Load unpacked option with extension/dist.
  2. Click the toolbar icon, then Open sharing controls. Keep that extension window open while sharing.
  3. Enter the exact server address and eight-character classroom code supplied by your teacher. Click Check classroom / join, and grant access to that server.
  4. If Google sign-in is required, click Sign in with Google & join and choose your approved school account. The backend rejects unapproved domains. For code-only classrooms, enter your name and student ID.
  5. Read the privacy/sharing disclosure and check the acknowledgement. Close private content in the screen/window you plan to select.
  6. Click Start Sharing. Select the intended screen or application window in Chrome's native picker and confirm. No webcam, microphone or audio is captured.
  7. Switch to VS Code, Jupyter, PyCharm or your other application. The teacher sees the selected source while it remains available. Full-screen capture is more reliable than minimized application-window capture on some systems.
  8. Check the sharing and recording indicators. Use Stop Sharing in the controls, toolbar popup or Chrome sharing indicator whenever you want to stop. Closing the extension controls also stops capture.

Teachers: view and record

  1. Run the backend and dashboard with a trusted HTTPS address reachable by all students. Sign into the teacher website.
  2. Create a course/session, then give students the server address and joining code. Students do not use a student website.
  3. Real images appear as students start sharing. Search by name or ID. Click a card to request a larger, higher-quality stream; close it to return to overview. Up to two distinct focused screens are allowed.
  4. Recording is off initially. If appropriate for your class, enable periodic screenshot recording and choose its interval. Inform students of the applicable policy. Live viewing and recording are independent.
  5. Open Playback to review timestamped screenshots. If configured, Google Drive receives ZIP batches rather than individual screenshot uploads.
  6. End the classroom when finished. Connected captures stop, and the old joining code becomes invalid.

One local network

The teacher can host the backend and dashboard on their computer. HTTPS is the default. In version 1.0.2, the teacher can explicitly enable trusted-LAN HTTP with ALLOW_LAN_HTTP=true, code-only joining, and a private IPv4 origin such as http://192.168.1.20:5173. Students enter that same address, tick Allow unencrypted HTTP on this Wi-Fi/LAN, and join by name/ID and classroom code. The teacher also uses that LAN address rather than localhost. Screenshots and passwords are unencrypted in this opt-in mode; Google sign-in and connecting Drive require HTTPS instead. Allow the dashboard port through the private-network firewall and check Wi-Fi client isolation. The Windows scripts/start_lan.ps1 -Address YOUR-IP launcher is described in the README. Code-only live sharing/local recording can work without internet after setup.

Troubleshooting

  • Connection failed: verify the full HTTPS server address, trusted certificate, active code, firewall and network reachability.
  • Domain rejected: use your managed school Google account; ask the administrator to confirm the exact allowed domain. Personal Gmail works only if gmail.com is allowed.
  • Blank/frozen source: check the selected window is still open and updating. Select the full screen if needed. On macOS allow Chrome Screen Recording in system settings and restart Chrome.
  • Long outage: capture stops after 30 seconds without the server. Reconnect, then click Start Sharing and choose a source again.

Installation does not prove capture works on every OS. Teachers should perform a real two-device acceptance test before classroom use. Full server deployment and Google OAuth configuration are described in the project's README.
